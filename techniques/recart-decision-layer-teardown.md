# Re:Cart 해체 — "머리 vs 손" 결정 계층 + 승리 요인 해부

> **맥락(냉정)**: 작가가 *떨어진* AX 인재전쟁 채널톡 트랙의 **1등** 작품(`ronut01/recart-ecommerce-agent`). read-only 해체(2026-07-20). **핵심 교훈은 씁쓸하지만 유용하다 — 이건 기술로 이긴 게 아니다.** 90줄 stdlib 서버 + 바닐라 JS + 결정론 룰 + 목업 데이터. 이긴 건 *포지셔닝 · 플랫폼 도메인 충실 · 심사 가독성 · 판매자 경제성 정렬* — 전부 작가의 홈그라운드(index)다. 더 화려한 챗봇은 이 작품에 진다.

## 승리 요인 해부 (왜 1등이었나 — 기술 아님)

### 1. 문제 재프레이밍 = 킬러 무브 ★
채널톡엔 이미 **ALF**(대화·업무 실행)가 있다. 대부분 참가자는 "또 다른 챗봇"을 만들었을 것. Re:Cart는 **"ALF는 손(실행), 우리는 머리(정책 결정)"**로 재정의 — *누구에게 / 무슨 혜택을 / 어디까지 허용할지*를 결정하는 계층. **플랫폼과 경쟁하지 않고 "완성한다".** = 인접 카테고리 창출로 차별화(포지셔닝 정석). 심사위원=채널톡 사람들에게 "당신 제품의 빈틈을 정확히 메웠다"로 읽힘.

### 2. 도메인 충실 (플랫폼 네이티브 어휘) ★
실제 채널톡 공식 문서(ALF 태스크·고객/상담 태그·CoS)와 Baymard 장바구니 이탈 연구(70.19%)를 읽고 인용. 출력이 **상담 태그**로 구조화돼 채널톡 CoS 분석에 *되먹임*. 심사위원의 제품 언어를 그대로 말함 = "우리는 당신 플랫폼을 깊이 안다" 신호.

### 3. 판매자 경제성이 코어 메커닉 ★
**"최소 유효 구조 행동"** — 가격 부담을 말해도 반사적으로 할인 X. 해결 후보(무료배송 3,500원 vs 7% 할인 9,000원)를 *추가 비용*으로 비교해 가장 싼 유효 행동 선택. 가드레일: 총 할인 ≤10% · 추가 비용 ≤5,000원 · 할인 후 판매자 이익 ≥25%. **VIP 관계는 후보를 넓힐 뿐 이익 하한을 완화하지 않는다.** AI를 고객 만족이 아니라 *판매자 P&L*에 정렬 — "할인 봇"이 마진을 태우는 반면 이건 지킨다. 진짜 사업 통찰.

### 4. 심사 가독성 (설명가능성) ★
비공개 사고과정이 아니라 `판단 근거 / 신뢰도 / 검증한 정책 / 선택 행동`만 노출. **고객 화면 ↔ 업체 화면 분리**(VIP 자격·마진·투자예산은 업체에만). 마이크로카피가 공헌이익률·%p 같은 내부어를 "기본 5%에 2%를 더해 총 7%"로 풀어씀. **평가받기 위해 설계된 UI** — 심사위원이 모든 결정을 검증 가능.

### 5. 결정론 런타임 (재현성)
"오프라인 심사에서 반복 재현" — 런타임은 결정론적 로컬 정책 엔진, LLM(Codex)은 *개발 과정만* 수행. 시연 중 환각 0. ← vault [Deterministic Core, Fuzzy Edge — 안티슬롭 아키텍처 원칙](../methods/deterministic-core-fuzzy-edge.md) 안티슬롭 패턴과 **동형**.

### 6. 정직한 한계 + 신뢰 신호
`SAMPLE DATA` 라벨, 명시적 §한계, 비가역·복합(환불·하자·감정고조)은 자동중지 후 인계. 과대주장 0 → 심사 신뢰 확보. ← 작가 §5.7 가역성 원칙·HITL을 *제품으로 구현*한 셈.

## 재사용 패턴 (뜯어갈 것)

- **결정 계층 vs 실행 계층 분리** — 실행 플랫폼(ALF/OMS/에이전트) 위에 "무엇을 허용할지 결정하는 정책 계층"을 얹는 아키텍처. 플랫폼과 경쟁 대신 보완. 어느 에이전트 제품에도 적용.
- **최소 유효 행동(Minimum Viable Action)** — 요구를 액면 수용 말고, *비용 오름차순 해결 후보*를 가드레일 통과 여부로 필터해 최저비용 유효안 선택. "발화 = 요구 혜택이 아니라 장애물의 단서".
- **비대칭 정보 UI** — 같은 결정을 이해관계자별로 다르게 노출(고객=제안+설명 / 운영자=근거+마진+예산). 심사·B2B 제품 공통.

## 적용 트리거 + 체크리스트 (다음 해커톤·공모·피칭용)

**언제 인출** — 해커톤·공모·제품 피칭·에이전트 제품 포지셔닝 준비 시.

- [ ] **플랫폼의 빈틈을 찾았는가?** 심사 주체의 기존 제품이 *이미 하는 것*을 다시 만들지 마라. 그 옆의 미충족 결정/정책 계층을 노려라("경쟁 말고 완성").
- [ ] **심사 주체의 어휘를 쓰는가?** 그들의 공식 문서를 읽고 네이티브 용어·데이터 구조로 출력을 되먹여라. 일반론 = 감점.
- [ ] **평가자의 진짜 관심에 정렬했는가?** (여기선 판매자 경제성 + 검증가능성). 고객 만족만 최적화한 화려한 데모는 이것에 진다.
- [ ] **모든 결정이 검증 가능한가?** 사고과정 대신 근거·정책·행동·결과를 노출. 이해관계자별 정보 분리.
- [ ] **시연이 결정론적인가?** 오프라인 심사에서 환각 없이 반복 재현. LLM은 개발에, 런타임은 결정론.
- [ ] **한계를 정직히 표기했는가?** SAMPLE DATA·미구현·인계 조건 명시 = 신뢰.

## 냉정 한계 (과대평가 가드)
- **기술은 사소하다** — 실제 채널톡·OMS·PG·태그 동기화 미연동, 전부 목업. 90줄 서버. 재현 난이도 낮음. *구현이 아니라 판단·프레이밍이 자산*.
- **실데이터 검증 0** — 한국어 의도 감지·정책 회귀·공정성·동의·A/B 전부 미구현(스스로 인정). "매출 지표"는 목업 계산 예시.
- **이식 주의** — 최소유효행동 엔진은 4개 시나리오 하드코딩. 실서비스는 실제 정책 규칙엔진 + 멱등 쿠폰 API 필요.

## delta / 관계 (작가 시스템)
- **선행 지향 ④**: 작가 vault는 이미 [Deterministic Core, Fuzzy Edge — 안티슬롭 아키텍처 원칙](../methods/deterministic-core-fuzzy-edge.md)(결정론 런타임)·§5.7(가역성·인계)·HITL을 *원리*로 보유. Re:Cart는 그 원리들을 *하나의 제품으로 응결*한 사례 — vault가 앞서 있되, "제품화 응결"은 배울 점.
- **홈그라운드 교훈**: 승부처가 index 포지셔닝 + market-language-map(심사 어휘) + impact-metric-ladder(검증가능 지표)였다 = 작가가 *이길 수 있었던* 싸움. 다음엔 기술 경쟁이 아니라 프레이밍 경쟁으로 접근.
- **반영처(Park)**: [학습→반영 루프 (Absorb-to-Apply)](../narrative/학습→반영 루프.md) ②Park — 다음 공모·피칭 준비 시 §적용 체크리스트 인출. 현재 active 응모(applications/*) 있으나 억지 주입 안 함(Karpathy #2). 트리거는 review_trigger에 명시.
- 아키텍처 쌍: 결정 계층 분리 ↔ [Agent–Human Parity — AI 행위자 참여 아키텍처](agent-human-parity-architecture.md)(행위자 참여 배선)와 인접 — 둘 다 "AI를 시스템에 *어떻게 앉히나*".
