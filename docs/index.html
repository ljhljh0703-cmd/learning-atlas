노트가 공개되기까지

비공개 노트 → 공개 저장소 · 한 방향

  1. 읽고 정리내 담당

    논문·저장소·도구를 읽고, 링크로 노트를 잇는 메모 앱 Obsidian에 출처·저자·연도와 함께 적습니다.

  2. 거르기

    공부 노트 폴더만 내보냅니다. 제안자·상태 같은 내부 기록 칸은 지우고, 비공개 노트로 가는 링크는 글자만 남깁니다.

  3. 검사

    이메일, 내 컴퓨터의 파일 경로, 비공개 폴더 링크가 하나라도 남아 있으면 그 주 발행을 멈춥니다.

  4. 발행

    주제별 목차와 이 페이지의 최근 노트 목록을 다시 만들고 공개 저장소에 올립니다.

그대로는 공개할 수 없던 노트

2026년 6월부터

  1. 문제

    공부한 내용은 채팅창에서 흩어졌고, 따로 적은 노트에는 내 컴퓨터 경로·이메일·지원서 폴더 링크가 섞여 있어 그대로 공개할 수 없었습니다.

    통째로 공개
  2. 판단

    비공개 노트에서 공개 저장소로 한 방향으로만 내보내는 도구를 만들었습니다. 원본 노트는 읽기만 하고, 출력 위치가 원본 폴더 안이면 바로 멈춥니다.

  3. 검증

    내보낼 때마다 막는 규칙 5개로 다시 훑습니다. 하나라도 걸리면 발행 스크립트가 거기서 끝나 저장소까지 올라가지 않습니다.

  4. 결과

    공개 노트끼리 걸린 링크는 저장소 안 링크로 바꿔 살렸습니다. 첫 공개 180편이 10월 19일 340편이 됐습니다.

왜 벡터 검색 대신 낱말 찾기와 그래프로 찾나참고한 연구 두 편

벡터 검색은 글을 숫자 묶음으로 바꿔 뜻이 비슷한 글을 찾는 방식입니다. 이 규모의 노트에서는 낱말을 그대로 찾는 grep과 노트 사이 링크를 따라가는 그래프 탐색을 기본으로 씁니다. 벡터 검색을 버린 것은 아니고, 이 규모와 용도에서는 더 가볍고 정확하다고 판단했습니다.

연구 1

Is Grep All You Need? (Sen 외, 2026)

LongMemEval 116문항을 4가지 에이전트 틀로 풀었을 때 grep이 벡터 검색보다 대체로 정확도가 높았습니다. 검색 방식보다 에이전트 틀의 설계가 점수를 더 좌우한다는 단서도 함께 나옵니다. arXiv 2605.15184

연구 2

Microsoft GraphRAG (Edge 외, 2024)

문서에서 뽑은 이름과 관계를 그래프로 엮고 묶음별로 요약하면, 문서 전체의 주제나 관계를 묻는 질문에서 단순 벡터 검색보다 낫다는 결과입니다. arXiv 2404.16130
