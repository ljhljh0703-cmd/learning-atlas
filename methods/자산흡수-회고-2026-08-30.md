# 회고 — 자산 흡수 2026-08-30

> 흡수한 것: 창작 원고(초파리 9판·동화 교정 쌍·암흑제국) + VD 외주 121파일(제안서 4·구성안 18·**스토리보드 24**·기타). 파생 노드 11종.
> 이 노트는 **산출물 목록이 아니라, 그 과정에서 드러난 축과 내 실패 기제**를 적는다.

## 1. ⭐ 전 도메인을 관통하는 축 — **판본은 「누가 고쳤는가」로 읽힌다**

창작과 외주가 따로 놀 줄 알았는데, 판본 대조를 쌓고 보니 **같은 축**이었다.

| 고친 주체 | 방향 | 실물 |
|---|---|---|
| 작가 자신 | 화자의 악의를 드러내는 쪽으로 | 초파리 9판 |
| 교정자 | 맥락에 맞춰 갈래를 튼다(정답이 아니라 선택지) | 동화 교정 2022 |
| 발주처 연구자 | **얹는다** (+23%) | 생기원 구성안 |
| 인터뷰이(고객) | **빈 자리에 근거를 채운다** | 배프 스크립트 |
| 내부 검토 | **늘린다** (+93%) | 스플렌더 룰 대본 |
| 납품 검수 | **순화한다** | 포용적 게임 디자인 |
| **광고주** | **판매 논리로 재배열한다** | 롯데렌터카 v5 |
| 클라이언트 회신 | **질문에 답을 채워 넣는다** | 폭스바겐 02.05 |

🔒 **다음 판본 쌍을 열 때 먼저 물을 것은 «무엇이 바뀌었나»가 아니라 «누가 왜 고쳤나»다.** 델타를 세는 건 그다음이다. 이걸 거꾸로 해서 게임 디자인 4판을 「반려」로 읽었고, 말투 지표를 세고 나서야 **제품이 갈린 것**임이 드러났다(개정-사례-대장-2022-2024 §4-4).

⚠️ 여덟 유형 전부 **같은 작가의 작업**이다. 「업계가 그렇다」가 아니라 「이 사람의 일이 이렇게 생겼다」로만 읽는다.

## 2. 두 번째 축 — **빈 자리를 「문장」으로 남긴다** (n=4, 네 장르)

| 실물 | 형태 |
|---|---|
| 배프 인터뷰 스크립트 | `[예시 대사] – 작성 필요` |
| 디지털트윈 SB | 자리표시자 컷 → 32분 만에 채워짐 |
| 폭스바겐 SB | `확인 요청사항) 서초 서비스 명칭 사용해도 되는지` → 클라 답이 같은 칸에 |
| vault 자체 | `[확인필요]` 필드 |

빈칸을 비워 두지 않고 **무엇이 왜 비었는지를 그 자리에 적는다.** 그래서 다음 사람(또는 다음 판의 자신)이 무엇을 해야 하는지 안다.
🔵 폭스바겐 건은 **방향이 반대**라 값지다 — 「작성 필요」는 *클라가 채울 칸*이고, 「확인 요청사항」은 *작가가 물은 것에 클라가 답한 흔적*이다. 같은 장치가 양방향으로 쓰인다.

## 3. 세 번째 축 — **분량 레버가 문서 안에 박혀 있다. 단, 층마다 단위가 다르다**

| 층 | 레버 | 실물 |
|---|---|---|
| 제안 | **%** | 실사 70 : 모션그래픽 30 (수산) |
| 구성안·스크립트 | **초** | `~46's … ~40's → 1차 총 분량 02:40's` |
| 구성안 | **괄호** | "(괄호)내 내레이션 생략 혹은 삽입 가능" |
| 전시 | **화면당 초** | `한 화면 당 30~45's` (아나몰픽) |
| **스토리보드** | **없다** | 24건 중 시간 표기 2건뿐 |

🔒 **원고가 없는 단계에선 %, 원고가 생기면 초.** 그리고 **SB 층에서 초를 찾지 마라** — 없는 게 정상이고, 초는 상류(구성안)에서 이미 세어져 내려온다. 이건 «못 찾은 것»이 아니라 **찾아보니 그 층에 없더라**는 결과다.

## 4. 🔴 내 실패 다섯 — 기제까지

### 4-1. 파일명으로 판정했다 (3회)

암흑제국 「퇴고.docx」가 실은 *퇴고 전* 원고였고, 법in카드 1128↔1129는 **md5가 같았고**(판본 쌍 아님), `수주에성공한홍보영상제작부문.pptx`는 **남의 회사 교재**였다(김형우/마런스, 무단복제 경고문 포함 → A1→A12 재분류).
⇒ 기제: **파일명은 저자의 의도이지 내용의 사실이 아니다.** `AS-27`이 이미 커버하는 자리이고, 이번에 **자사 산출물에서도 같은 일이 일어난다**는 게 확인됐다(§4-4).

### 4-2. 🔴 문서의 「장치」와 작업의 「문법」을 구분 못 했다 — **작가 직접 교정**

스토리보드 성격을 보고하면서 「수정 내용 해당 박스를 활용해서 기재부탁드립니다」 칸이 내장돼 있다는 걸 **핵심 발견처럼** 올렸다. 작가: *"이건 중요한 게 아님."*
⇒ 기제: 그건 **템플릿 기본 안내문**이지 작가의 판단이 아니다. 문서에 있다고 다 문법이 아니다.
🔒 **판별 기준 — 판단이 개입한 자리만 문법이다.** 매 문서에 똑같이 박혀 있으면 서식이고, 건마다 다르면 그게 문법이다. 폭스바겐의 「확인 요청사항」은 건마다 내용이 다르므로 문법이고, 「수정 내용 박스」는 전 건 동일하므로 서식이다.

### 4-3. 「흡수 완료」와 「문법 파악」을 같은 말로 보고했다 — **작가 질문에 드러남**

*"다 흡수하고 자산화 함? 이제 구성안과 스토리보드 좀 파악했냐."* — 물어보시기 전까지 나는 **미개봉 0건**을 완료로 보고하고 있었다. 실제로 구성안은 해부 노드가 있었지만 **스토리보드는 24건 중 2쌍만 컷 단위로 열었을 뿐**이었다.
🔒 **두 단계를 갈라 보고한다** — ① **개봉·분류**(파일이 몇 건, 갈래가 몇 개) ② **해부**(문법을 몇 건에서 뽑았나). ①만 끝났으면 ①만 끝났다고 말한다. 「전량 흡수」는 ①의 표현이지 ②의 표현이 아니다.

### 4-4. 측정을 한 번 돌리고 결론 낼 뻔했다

화면 지시 블록 길이를 정규식 한 벌로 재고 「갈래별 문법」이라 부르려 했다. **규칙을 바꿔 재측정하니 공공(디지털트윈)이 61자↔102자로 흔들렸다.** 흔들린 행은 표에서 뺐다.
🔒 **분류 규칙 하나로 낸 수치는 규칙을 바꿔 한 번 더 돌린다.** 두 번 다 같은 방향이면 쓰고, 흔들리면 버리거나 한계로 적는다.

### 4-5. 「매몰되지 마라」를 듣고 나서야 멈췄다

이미지형 PDF 49~76장을 전수 판독하려 했다. 작가: *"매몰되진 마라. 검증은 하되."* 이후 지각 해시 대조 + 표적 판독으로 바꿨고 그게 더 나은 결과를 냈다(수산 76→70p 델타는 **전수 판독으로는 못 봤을** 구조 변화였다).
🔒 **전수 판독보다 전수 «대조»가 먼저다.** 싸게 전부 비교해 다른 곳을 찾고, 비싼 판독은 거기에만 쓴다.

## 5. 무엇이 반복돼 스킬화 후보인가 (⑤ 보고, 생성은 작가 승인 후)

같은 절차를 이번 세션에 **네 번** 돌렸다 — 이식 폴더 / 업무 폴더 1차 / 업무 폴더 갈래별 / 스토리보드 전수.

```
외부 저장소 목록화(메타데이터만)
  → 갈래 가설 세우고 작가 확인
  → 본문 추출(형식별 파서) → raw/ (git 밖)
  → 갈래별 사례 노드 (⛔ 규칙집 아님 · n수 표기)
  → 판본 쌍은 «누가 고쳤나»부터
  → index·log 반영 · 하네스 후보는 관측으로만
```

**후보 이름**: `asset-absorb` (외부 자산 → vault 사례 대장). 🙋 작가 승인 대기.
⚠️ 기존 `package-project-evidence`와 겹치는지 먼저 봐야 한다 — 저건 *증거 패킷*, 이건 *사례 대장*이라 목적이 다르지만 앞단(목록화·추출)이 같다.
