# Argdown — 결정 근거를 논증 지도로 그리기

> ⚠️ 임시 — 결정 기록 1건 시험 적용 단계. 계속 쓸지는 아래 §판정 기준으로 정한다.

## 한 줄 요약
> 마크다운처럼 글로 적으면 **주장 · 지지 · 반박 · 근거 깎기**가 화살표 그림으로 나온다. 결정 기록의 「왜」를 한 장 그림으로 보여 주는 도구.

## 문법 최소선 (이 정도면 쓴다)

| 쓰는 법 | 뜻 |
|---|---|
| `[이름]: 문장` | 주장(명제) |
| `<이름>: 문장` | 논거(근거 덩어리) |
| 들여쓰기 + `+ <논거>` | 위 주장을 **지지** |
| 들여쓰기 + `- <논거>` | 위 주장을 **반박** |
| 들여쓰기 + `_ <논거>` | 위 논거의 **추론 고리를 깎음**(결론은 그대로 두고 근거→결론 연결만 약화) |
| `(1) … (2) … ---- (3)` | 전제→결론 구조로 풀어 쓰기 |

- 한 번 정의한 `<이름>` 은 다른 곳에서 이름만 불러 재사용한다.
- 렌더: `npx -y @argdown/cli map --format svg <파일> <출력폴더>` (임시 실행 — vault 에 설치 없음). 문법 검사만 = `… json …`.

### 그려 보고 드러난 것
1. **논문 근거는 혼자서는 약하다.** 결정을 받치는 유일한 실험 근거(논문 실측)를 **같은 논문이 스스로 깎는다**(점수는 검색 방식보다 하네스가 좌우). 글로 읽을 땐 「과장 가드」 한 줄로 지나갔는데, 그림에선 근거 화살표에 깎기 화살표가 바로 꽂힌다.
2. **결정이 버티는 이유는 독립 근거 3개다** — 논문 + 토큰 절약 + 보안 비용. 논문이 무너져도 나머지 둘이 남는다. 「이 결정을 다시 볼 때 무엇이 바뀌면 뒤집히나」가 그림에서 바로 읽힌다(토큰 비용·보안 비용이 둘 다 사라질 때).
3. **반박이 이미 처리됐는지 한눈에 보인다** — 「동의어 누락」 반박은 2-패스 보완으로 막혀 있다(반박의 반박).

### 비용
- 이번 1건 작성 약 25줄 · 렌더 명령 1회. 노트 안 그림은 SVG 파일로 붙여야 보인다(Obsidian 자체 렌더 없음).

## 판정 기준 (계속 쓸지)
- **쓴다**: 근거 3개 이상 + 반론이 실제로 있는 큰 결정(위성 문서 풀세트급, CLAUDE.md §의사결정 일반 워크플로우의 「큰」 결정).
- **안 쓴다**: 근거 1~2개짜리 작은 결정 — 표 한 줄이 더 싸다.
- 재검토: 큰 결정 2건 더 그려 본 뒤, 그림이 결정을 바꾸거나 빠진 근거를 잡은 경우가 0건이면 강등.

## 학습→반영
- 반영 판정 = **② 파킹** — 다음 「큰」 결정 상신 때 그림 1장 첨부를 시험(트리거: 큰 결정 브리프 작성 시). 지금 워크플로우 문서 수정은 안 함(시험 1건으로는 근거 부족).
