# Paseo 해체 — 전송층은 사고 싶고, 오케스트레이션층은 사면 안 된다

> **한 줄**: 내 기계에서 Claude Code·Codex·Copilot·OpenCode·Pi 를 **하나의 데몬**이 돌리고, 폰·데스크톱·웹·CLI 어디서든 붙는다. **원격 접근이 부가기능이 아니라 구조 자체다.** 그런데 그 위에 얹힌 에이전트-간 오케스트레이션의 기본값은 **사람을 루프에서 빼는 방향**이라, 작가 헌법과 정면으로 부딪힌다.

## 1. 구조 (실측)

```
[폰·데스크톱·웹·CLI]  ──E2EE 릴레이 or 직접TCP──▶  [데몬 1개 / 내 기계]
                                                      │
                                    child_process.spawn (PTY 아님)
                                      ├─ claude  (Anthropic SDK, spawn 훅 가로챔)
                                      ├─ codex   (JSON-RPC over stdio)
                                      ├─ copilot (ACP over stdio)
                                      ├─ opencode(로컬 HTTP 서버 + SSE)
                                      └─ pi / omp(JSONL-RPC over stdio)
```

- **데몬 1개 = `PASEO_HOME` 1개** (pid 락). 모든 클라이언트가 **같은 AgentManager 를 구독**한다 → "책상에서 시작, 폰에서 확인"은 **코드로 뒷받침된다**(마케팅 아님).
- 에이전트 실행은 **클라이언트 소켓과 분리**돼 있다. 폰을 꺼도 돈다. 소켓 끊겨도 세션은 90초 유예 후 정리되지만 **에이전트는 안 죽인다.**
- **데몬이 죽으면 자식 프로세스도 죽는다.** 복구는 프로세스 생존이 아니라 **provider 세션 핸들로 지연 재개** — 대화는 살아남고 **진행 중이던 작업은 날아간다.**
- 🔴 **타임라인은 디스크에 안 남는다**(`InMemoryAgentTimelineStore`). 재시작 후 보이는 대화록은 provider 원본을 되읽어 **재구성한 것**이다. 내구 저장소 옵션은 코드에 있으나 프로덕션에서 연결되지 않는다.

## 2. 작가 현재 방식과의 대조 — 이게 핵심이다

| 지금 하는 일 | Paseo 로 하면 |
|---|---|
| `CODEX-DISPATCH-*.md` 손으로 써서 Codex 에 넘김 → `~/Documents/Codex/` 에 RETURN 떨어짐 → 내가 게이트 | `/paseo-handoff` = **같은 구조의 자동판**(9절 템플릿: 과제·맥락·파일·현재상태·시도한 것·결정·수용기준·제약) |
| Codex 산출물을 파일로 주고받음 | 데몬이 프로세스를 직접 물고 있어 **스트리밍·중단·후속 지시** 가능 |
| 세션 끊기면(device bridge 단절) 작업 중단 | 데몬이 살아 있으면 **작업은 계속**, 폰으로 붙어서 확인 |
| 병렬 작업 = 세션 여러 개 수동 | worktree 격리 + 병렬 에이전트가 **일급 기능** |
| 예약 작업 = 이 세션의 scheduled task | `create_schedule` / `create_heartbeat`(에이전트가 **스스로 재기동 예약**) |
| 문체·게이트 규율 = vault 문서 | 스킬 6종이 `~/.claude/skills`·`~/.codex/skills` 에 **자동 동기화** |

⭐ **작가의 Dual-Track 은 이미 Paseo 의 handoff 와 같은 모양이다.** 다른 건 하나 — **작가 것은 게이트가 사람이고, Paseo 것은 게이트가 부모 에이전트다.** 아래 §4.

## 3. 직접 재검증한 주장 (요약을 믿지 않고 소스 실독)

| 주장 | 판정 | 근거 |
|---|---|---|
| "폰에서 이어받기" | ✅ **사실** | 데몬 1개·공유 AgentManager·세션별 구독 |
| "병렬 실행" | ⚠️ **되지만 무방비** | 동시 실행 **상한·큐·자원 제한 전무**. N 에이전트 = N CLI 프로세스. OpenCode 는 서버 프로세스를 **공유**(refcount)해 격리도 아님 |
| "텔레메트리·추적·강제 로그인 없음" | ⚠️ **대체로 사실, 단서 3** | 분석 SDK·크래시 리포터 **0건**(전 패키지 의존성 검색). 단 ⓐ **모바일 푸시가 에이전트 출력 220자 미리보기를 Expo→FCM/APNs 로 평문 전송**(권한 허용 시 자동 켜짐, 개인정보처리방침에 푸시 언급 없음) ⓑ 데스크톱 앱이 **자동 업데이트 확인 + 영구 설치 UUID** 보유 ⓒ 마케팅 사이트는 Plausible 사용 |
| "코드는 내 기계를 떠나지 않는다" | 🔴 **푸시 경로에서 깨진다** | 위 ⓐ. 권한 프롬프트 알림은 **도구 인자를 `JSON.stringify` 해서** 본문에 넣는다 |
| 릴레이 E2EE | ✅ 진짜 (X25519 + XSalsa20-Poly1305) | 단 **전방 비밀성 없음**(데몬 키 영구) · **세션 내 재전송 방지 없음**(SECURITY.md 자인) · 릴레이는 **인증을 전혀 안 한다** |
| worktree 문서 "base 브랜치의 커밋된 paseo.json 을 읽는다" | 🔴 **부정확** | 코드는 워크트리 것을 읽고, 브랜치에 없으면 **작업 사본의 untracked `paseo.json` 을 복사해 넣고 그 setup 을 실행**한다 |

## 4. 🔴 헌법과 정면 충돌 — 3건

### ① 자식 에이전트의 승인 요청이 **사람이 아니라 부모 에이전트에게 간다**

알림 본문이 부모에게 이렇게 조립된다 — *"Respond with `respond_to_permission` using the `agentId` and `requestId` below."* 설계 의도가 그렇게 적혀 있다.
게다가 `respond_to_permission` 툴에는 **소유권 검사가 없다.** `list_pending_permissions` 는 **데몬 전체의 대기 중 권한 요청을 전부** 돌려준다(툴 설명 원문: *"Return all pending permission requests across all agents"*). 즉 **아무 에이전트나 내 메인 에이전트의 권한 요청을 승인할 수 있다.**
→ 절대룰 #7(초안 주체가 자기 판정 규격을 발행 금지) · Doer-Verifier 격리 · HITL 스테이징 **전부와 충돌**.

### ② 위험한 설정은 상속되고, 안전한 설정은 상속되지 않는다

모드 상속 코드는 세 갈래다:
- 같은 provider → **부모 모드를 조용히 물려받는다**
- provider 가 다른데 **부모가 무인 모드면** → 대상 provider 의 **무인 모드를 준다**
- 그 외 provider 가 다르면 → **던진다**(명시 요구)

즉 편하려고 부모를 `bypassPermissions` 로 두면, **다른 gesture 없이** 모든 자손이 모든 provider 에서 프롬프트 생략 모드가 된다(Claude bypass → Codex `danger-full-access`). **비대칭이다 — 위험한 쪽만 전이된다.**
그리고 **예약 실행은 기본이 무인 모드다.** 권한 프롬프트를 만나면 기다리는 게 아니라 **실행을 실패시킨다** — 그래서 무인 모드가 사실상 필수가 된다.

### ③ 데몬 접근 = 그 사용자 계정 완전 장악

- 비밀번호 미설정이면 **소켓에 닿는 것이 곧 권한**이다(프로젝트 자신이 "Docker 데몬과 같은 모델"이라고 명시). `PASEO_LISTEN=0.0.0.0` + 무비번 = **원격 완전 개방**, 데몬 쪽 경고나 거부 없음.
- 모든 세션이 **owner 권한 전량**을 받는다. 역할 분리 없음.
- 터미널 생성·키 입력에는 **권한 게이트가 아예 없고**, cwd 도 워크스페이스로 제한되지 않는다.
- **페어링 오퍼 = 만료도 폐기도 없는 영구 자격증명.** 기기 목록도 없어서 누가 붙었는지 볼 수도 없다. 이미 붙은 클라이언트는 **새 오퍼를 스스로 발급**할 수 있다.
- ⚠️ **릴레이 클라이언트에는 데몬 비밀번호가 적용되지 않는다**(별도 경로로 owner 승인). 어느 문서에도 안 적혀 있다.
- ⚠️ `config.json` 이 `daemon.relay.enabled` 를 **생략하면 릴레이가 켜진다**(2027-01-31 까지 호환 조항). 공식 Tailscale 안내대로 `daemon.listen` 만 적으면 **모르는 채로 릴레이가 켜진다.**

### 부수 — `<paseo-system>` 봉투가 이스케이프되지 않는다

자식 출력이 `<agent-response>` 안에 **잘리기만 하고 이스케이프 없이** 부모에게 주입된다. 자식이 `</paseo-system>` 을 출력하면 봉투가 조기에 닫히고 그 뒤 내용은 **신뢰 표지 밖에서** 부모에게 도착한다. 전달 방식도 `steer` 라 부모의 진행 중인 턴에 끼어든다.

## 5. 도입 판정 — ✅ **전면 도입 (작가 2026-08-31)**

> **판정 완료.** 실행 계약 정본 = paseo-adoption-2026-08-31 · 결정 등재 제안 = `스테이징 영역`(D-006, 작가 merge 대기). 아래는 그 판정의 근거와 계약 원문이다.

「외부 도구는 설치 말고 해체해 흡수」🔒 는 **인프라 레이어를 들이지 말라**는 규율이고, Paseo 는 정확히 그 인프라(데몬)다. 그러나 이 건은 예외 심사 대상이다 — **작가의 병목이 지식이 아니라 전송이기 때문이다.** device bridge 단절·Codex 파일 왕복·폰에서 못 붙음은 문서로 못 고친다.

**기본값을 거슬러 설정해야 한다. 설정 계약 — 확정:**

| # | 설정 | 왜 |
|---|---|---|
| 1 | `mcp.injectIntoAgents` = **off 유지**(기본값 off) | 켜는 순간 §4① 의 권한 승인 툴이 모든 에이전트에게 열린다 |
| 2 | `pluginsEnabled` = **off 유지**(기본 off) | 플러그인은 샌드박스 없이 데몬 기계 전권, 매니페스트에 권한 선언 칸이 **아예 없다** |
| 3 | 데몬 **비밀번호 필수** + `listen` 은 127.0.0.1 고정 | 무비번+0.0.0.0 = 원격 완전 개방 |
| 4 | `daemon.relay.enabled` 를 **명시로 `false`** | 생략 = 켜짐 |
| 5 | 원격은 **Tailscale 등 VPN** 경유 | 데몬에 TLS 없음 — 직접 TCP 는 비밀번호가 평문으로 흐른다 |
| 6 | 무인 모드(`bypassPermissions`·`full-access`) **금지**, 예약 실행은 **명시 modeId** | §4② 전이 차단 |
| 7 | 모바일 푸시 알림 **끄기** | 에이전트 출력이 Expo/FCM 을 거친다 |
| 8 | vault 경로는 **워크스페이스에 넣지 않는다** | 파일 API 의 루트가 클라이언트 지정이라 `/` 도 정당화된다. 헌법·SSOT 는 사거리 밖에 둔다 |
| 9 | ③Gate 는 **Paseo 밖에 남긴다** | 부모 에이전트가 자식을 승인하는 구조를 게이트로 쓰면 절대룰 #7 위반 |

⛔ **Hub 는 도입 후보에서 뺀다.** GitHub·Slack·Discord 이벤트가 내 기계에서 에이전트를 띄우는 구조인데, 데몬 쪽 cwd 검사가 **"절대경로이고 비어있지 않다"가 전부**다. 허용목록도 프로젝트 제한도 없다. 문서 자신이 *"프로바이더 프로세스를 샌드박스하지 않고 외부 텍스트를 안전하게 만들지도 않는다"* 고 적는다.

## 6. 성숙도 (도입 판단 재료)

- **0.7.0-beta.3**, Apache-2.0, 태그 없음.
- 최근 20일에 **373 커밋** — 매우 빠른 변화. 그만큼 오늘 읽은 코드가 다음 달에 유효하다는 보장이 약하다.
- 🔴 **버스 팩터 1** — 커밋의 **78%(292/373)가 1인**. 나머지는 봇과 산발 기여.
- 테스트 파일 **1,223개** — 이 규모 프로젝트치고 진지하다. 데몬 재시작→재개 e2e 테스트가 실재한다.
- Claude 모델 목록만 **소스에 박제**돼 있다(다른 provider 는 런타임 조회). 신모델은 Paseo 릴리스를 기다려야 하고, 우회는 `~/.claude/settings.json` 에 직접 적는 것.

## 7. provider 갈아탈 때 조용히 깨지는 것

한 대화를 **다른 provider 로 이어받을 수 없다**(재개 핸들이 provider 에 묶여 있고 네이티브 세션 포맷이 서로 다름). 유일한 경로는 대화록을 **평문 텍스트로 떠서 새 에이전트에 붙여주는 것** — 추론 블록·todo·이미지·도구 입력·권한 이력은 **버려진다.**

그 외: rewind 는 Claude 만 3종 완비(Copilot 은 전무) · **턴 진행 중 후속 입력이 Claude/Codex/OpenCode 에서는 "덧붙이기", Copilot/Pi/OMP 에서는 "턴을 죽이고 재시작"** (같은 키 입력, 반대 결과, 경고 없음) · 권한 모드 id 는 provider 간 **겹치는 게 하나도 없다**(Pi 는 모드 자체가 없음) · 스킬 동기화는 **Claude·Codex 디렉토리에만** 간다.

## 8. 이 해체가 확인하지 못한 것

- 실제 배포된 릴레이(별도 Elixir 저장소) 의 동작 — 저장소 안의 Cloudflare 구현만 봤다.
- Hub 서버 본체(별도 배포) — 트리거 매칭·`from_users` 강제·토큰 발급.
- **실행 검증 0** — 설치·기동을 하지 않았다. 위 판정은 전부 소스 판독이다.
- 모바일/데스크톱 UI 가 서버에 없는 안전장치를 추가로 걸어주는지.
