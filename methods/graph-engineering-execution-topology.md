# Graph Engineering — 실행 토폴로지 (≠ 지식 그래프)

## 0. ★ 먼저 용어 분리 — 이걸 안 하면 흡수가 오염된다

vault 에는 이미 "그래프"가 있다. **둘은 다른 대상이다.**

| | **graphify 그래프**(vault 기존) | **본 노트의 그래프**(실행 토폴로지) |
|---|---|---|
| 노드 | 개념·파일·엔티티 | **일감 1건**(에이전트 1호출) |
| 아리스타 | wikilink·시맨틱 관계 | **데이터 핸드오프**(A의 return 이 B의 prompt 로 들어감) |
| 목적 | 무엇을 아는가 / 무엇과 연결되는가 | **무엇이 무엇을 기다리는가** |
| 산출 | `graph.json`·커뮤니티·질의 | 실행 시간·비용·신뢰도 |
| 수명 | 영속(vault 자산) | 실행 1회(스크립트는 `.claude/workflows/` 에 영속) |

→ **혼동 금지**: 오케스트레이션에 graphify 를 쓰거나, 지식 탐색에 workflow 를 쓰는 건 대상 오인이다.

## 1. 작가 읽음 정정 — "하네스 → 루프 → 그래프"는 사다리가 아니다

원문 명제: *"프롬프트는 문장이다. 루프는 사이클이다. **하네스는 에이전트가 딛고 서는 바닥이다.** 그러나 일 자체의 형태 — 무엇이 무엇보다 먼저 도는가, 무엇이 동시에 돌 수 있는가, 무엇이 나머지 전부를 기다려야 하는가 — **그 형태가 그래프다.**"*

즉 상승 단계가 아니라 **같은 시스템을 보는 4개의 축**이고, 그래프는 *빠져 있던 축*이다. 하네스를 아무리 잘 깔아도 일의 형태가 일렬이면 일렬로 돈다. (작가 직관 "이어지는 흐름"은 방향은 맞다 — 다만 그래프가 하네스의 *상위 단계*가 아니라 하네스가 답하지 않는 *다른 질문*이다.)

## 2. 14단계 — 4블록 압축

### 블록 1 (01~04) · 이미 있는 그래프를 보기
- **01. 노드=일감, 아리스타=흐르는 것.** 아리스타는 **데이터가 실제로 건너갈 때만** 존재한다. *"이 파일 요약하고 **그리고 나서** 날씨 알려줘"* 에는 아리스타가 없다 — 날씨는 요약을 소비하지 않는다. **"그리고 나서" ≠ 아리스타.** 화살표를 못 그리면(변수가 안 건너가면) 두 상자는 독립이다.
- **02. 당신의 선형 스크립트는 이미 그래프다 — 퇴화된.** A→B→C→D 는 분기 없는 사슬. 대부분의 사슬엔 데이터를 나르지 않는 화살표가 2~3개 있고, 그건 **타이핑한 순서일 뿐**이다. 잘라내면 사슬이 넓어진다. **비용 0·새 도구 0.**
- **03. 노드마다 계약.** 입력 한정·출력 한정·일 하나. 워크플로에서는 `schema` 로 강제하고 **검증이 tool-call 레이어에서 일어나 불일치 시 재시도**된다(자유 텍스트 파싱+기도 X). *"출력에 형태가 없으면 노드가 아니라 대화다."*
- **04. 아리스타도 계약이고, 게다가 공짜.** ★ fan-out 과 합성 사이의 축약(평탄화·중복제거·필터)은 **JS 평문**이다. *"에이전트는 판단용이지 배관용이 아니다. 모든 아리스타가 에이전트인 그래프는 자기 배선에 월세를 낸다."* 합치기가 flatMap + Set 이면 결정론·즉시·0토큰.

### 블록 2 (05~08) · 함대 움직이기
- **05. `parallel()` 로 부채꼴 펴기.** N개 독립 노드를 줄 세우지 말고 동시에. **배리어**(전부 기다림) · 예외 던진 thunk 는 **null 로 resolve**(배치 전체를 죽이지 않음) → 그래서 항상 `.filter(Boolean)`. 동시성은 코어 수 부근에서 상한, 초과분은 큐. **핵심**: fan-out 이 *Claude 가 쓴 코드* 안에 살기 때문에 Claude 컨텍스트는 9개 소스를 동시에 들지 않는다. **오케스트레이션 계층은 0토큰**(대화가 아니라 코드라서).
- **06. 배리어로 닫기.** fan-in = 아리스타들이 수렴하는 노드. **전체 집합이 진짜 필요할 때만** 배리어가 값을 한다(교차 중복제거·전량 기준 조기종료·"다른 발견들과 비교" 프롬프트). *평탄화만이면 그건 아리스타다 — 인라인으로.*
- **07. 다이아몬드: 쪼개고, 일하고, 합친다.** 정식 이름 **fan out → reduce(평문 코드) → synthesize(에이전트)**. 시장 스캔·의존성 감사·코드 리뷰·리서치 보고서의 공통 골격. *"단계를 설계하지 말고, 어디서 갈라지고 어디서 합치는지를 설계하라."*
- **08. 런타임 라우팅.** 라우터 노드가 결과를 보고 어느 아리스타가 발화할지 정한다. 워크플로에선 검증된 출력에 대한 평범한 `if`/`switch`. ★ *"모델이 **이게 뭔지**를 판단하고, 코드가 **그걸로 뭘 할지**를 결정한다."* 결정론이 제약이 아니라 기능 — "에이전트가 감사를 건너뛰기로 했다" 같은 창발적 사고가 불가능하다(그 점프가 그래프에 안 적혀 있으므로).

### ★ 역규칙 (블록 3 전에 읽으라고 원문이 명시)
> **그래프는 *폭*을 사지 *판단력*을 사지 않는다.** 작업의 매 단계가 이전 단계의 전체 그림을 필요로 한다면, 에이전트들에게 나눠도 **같은 답을 더 비싸고 더 늦게** 얻을 뿐이다. 그래프는 *작업이 서로의 결과를 읽지 않는 일감으로 쪼개지는 순간*부터 값을 한다.
> **에이전트 하나 추가하기 전 유일한 질문: "내 작업은 어디서 갈라지는가?"** 안 갈라지면 단일 에이전트로 남고 나머지 6단계를 아껴라.

### 블록 3 (09~11) · 나온 것을 신뢰하기
- **09. 아리스타 위에 검증자.** 레버는 에이전트 수가 아니라 *그 주변에 세우는 신뢰 구조*. 검증 노드는 결과가 하류로 내려갈 권한을 얻기 전에 앉아서 **그 발견을 죽이려 시도**한다. **철칙: 같은 에이전트가 자기 시험을 채점하게 두지 마라**(틀린 자리에서 평가하므로 자기 오류 대부분을 놓친다). 3패턴 — **적대적 검증**(N 회의론자, 다수 생존 시 통과) / **다중 렌즈 검증**(검증자마다 다른 각도: 정확·보안·재현 — 동일 검사 N회가 못 잡는 실패 모드를 잡음) / **심판 패널**(N 시도 → 병렬 채점 → 승자 기반 합성 + 준우승 장점 이식).
- **10. 노드 격리로 오염 차단.** 사슬에선 실패가 캐스케이드하지만 그래프에선 노드에 갇혀야 한다. `parallel()` 의 null resolve + `.filter(Boolean)` 이 1차 봉쇄, **모든 fan-in 은 결측 입력을 견디게** 설계. 더 미묘한 건 노드끼리 밟는 것 — **병렬로 파일을 쓸 때만** git worktree 격리. *"그게 필요한 유일한 토폴로지의 안전벨트지 모든 실행에 매기는 세금이 아니다."* → **파일당 작성자 1명.**
- **11. 사이클은 되 수렴하게.** 크기를 모르는 발견(버그 스윕 등)엔 되돌아가는 아리스타가 필요하다. 수렴 패턴 = **loop until dry**(K회 연속 신규 0이면 정지). ★ **거의 모두가 처음에 틀리는 지점 = 무엇에 대해 중복제거하는가.** **"본 것 전체"에 대해 dedupe 하라. "확정된 것"에 대해서가 아니라.** 아니면 기각된 발견이 매 라운드 재등장해 영원히 마르지 않는다.

### 블록 4 (12~14) · 파산하지 않기
- **12. 노드 간 모델 계단화.** ★ 함정: **서브에이전트는 기본적으로 세션 모델을 상속**한다 → 큰 실행이 통째로 세션 등급으로 과금된다. `agent()` 의 `model` 옵션으로 *그 노드만* 강등. 지루하고 반복적인 fan-out 노드는 싼 모델, **판단이 걸린 융합 노드는 위에 유지.**
- **13. 토폴로지가 곧 비용이자 지연.** `parallel()`(배리어) vs `pipeline()`(무배리어, 항목 A가 3단계일 때 B는 1단계 가능). **기본은 pipeline**, 배리어는 정당화된 예외만. *"더 깔끔해 보인다"·"단계가 분리된 느낌"은 이유가 아니다 — 배리어 지연은 실측 가능한 낭비다. 분리 ≠ 동기화.*
- **14. Claude 에게 그래프를 그리게 하라.** 매 실행마다 형태가 바뀌는 작업은 손으로 안 그린다. 진입 3경로 — 프롬프트에 "workflow" / 저장·번들 워크플로 실행(**`/deep-research` = 실제 운영 중인 그래프**: 범위한정 → 병렬검색 → fetch → 적대적 검증 → 합성) / 매 작업 워크플로 계획 모드. 잘 나온 실행은 **`.claude/workflows/` 에 저장** → 버전관리·이름 재실행·클론한 누구나 실행.

## 3. 발사 전 체크리스트 (원문 10문항)

데이터를 안 나르는 아리스타를 지웠나 · 작업이 진짜 갈라지나 · 노드마다 입력한정·출력형태·단일업무인가 · flatMap 이면 될 걸 에이전트에 돈 내고 있나 · 전체 집합이 불필요한 배리어가 있나 · 아무도 죽이려 시도하지 않은 발견이 결과에 닿나 · 검증자 둘이 같은 질문을 하나 · 모든 루프에 라운드 상한이 있나 · 같은 파일에 쓰는 노드가 둘 이상인가 · 반복 노드가 비싼 모델로 도나.
> **3개 이상 실패면 그래프가 아니라 "단계가 더 많은 사슬"이다.**

## 4. 신뢰도 판정 — 기술 내용은 공식 계약의 고충실 재진술

본 세션 런타임의 **Workflow 도구 계약과 직접 대조**했다. 아래가 계약과 **일치**한다: `parallel()` = 배리어 · 예외 thunk → null · `.filter(Boolean)` 권고 · **"DEFAULT TO pipeline()"** · loop-until-dry 의 *"dedup vs seen, NOT confirmed — 아니면 수렴하지 않는다"* 경고 · 적대적/다중렌즈/심판패널 3패턴 명칭 · worktree 는 **병렬 쓰기 시에만**(기본 세금 아님) · `model` 미지정 시 **세션 모델 상속** · schema 검증이 tool-call 레이어에서 재시도 · 동시성 코어 기반 상한 + 초과분 큐 · `.claude/workflows/` 저장.

→ **결론: 기술적 신규성은 0에 가깝다. 값은 전부 *교육적 프레이밍*에 있다.** 공식 계약은 "무엇이 가능한가"를 적고, 이 글은 **"당신 시스템의 어디가 이미 틀렸는가"** 를 묻는다. 그 진단 질문들이 이식 대상이다.
⚠️ 단 수치 1건 불일치 — 원문은 동시성을 *"대략 코어 수"* 로만 말하고, vault [Dynamic Workflows — 작업마다 하네스 (Claude Code)](dynamic-workflows-harness.md) 는 **동시 16 / run 당 총 1,000** 을 기록(공식 docs 검증분). 본 세션 계약도 `min(16, cores-2)` · 총 1,000. **원문보다 vault 기록이 정확하다.**

## 5. vault delta — 무엇이 새롭고 무엇이 중복인가

**중복** ([Dynamic Workflows — 작업마다 하네스 (Claude Code)](dynamic-workflows-harness.md) 2026-06-15 가 이미 보유): JS 오케스트레이션 스크립트·백그라운드 격리·중간결과가 스크립트 변수에 머묾·트리거·런타임 상한·단계별 모델 라우팅·`.claude/workflows/` 저장·`/deep-research` 번들·7패턴(Classify-and-act, Adversarial verification, Fan-out-and-synthesize, Loop until done 등)·**이식성 등급**(vault 고유 각도, 원문에 없음).

**신규 (본 노트의 순증)**
1. **노드/아리스타 모델링 어휘** — vault 는 *패턴* 단위였지 *그래프 프리미티브* 단위가 아니었다.
2. **"그리고 나서" ≠ 아리스타** 진단 — 가짜 아리스타 탐지법. vault 전무.
3. **"아리스타는 공짜, 에이전트는 판단용이지 배관용이 아니다"** — 배관을 에이전트로 하면 자기 배선에 월세. **최대 비용 레버이고 vault 전무.**
4. **역규칙**("그래프는 폭을 사지 판단력을 사지 않는다" + "어디서 갈라지는가") — vault 는 "복잡·고가치 작업에만"이라는 *임계* 는 있었으나 **왜 안 되는지의 원리**가 없었다.
5. **`parallel` vs `pipeline` 기본값 판정** — vault 노드에 두 이름 모두 부재. 지연 레버.
6. **loop-until-dry 의 dedupe 대상 함정**(본 것 vs 확정된 것) — vault 전무.
7. **다이아몬드 명명 + "단계 말고 절단·융합 지점을 설계"** — 사고 전환.
8. **"모델이 무엇인지, 코드가 무엇을 할지"** 라우터 결정론 — vault Classify-and-act 에 없던 프레이밍.
9. **모델 상속 함정**(미지정 시 세션 등급 전량 과금) — vault §4 모델 라우팅에 이 함정 서술 없음.
10. **발사 전 10문항 체크리스트.**

## 6. 기존 vault 교리와의 관계

- **09(생성≠검증, 자기 채점 금지)** = hermes-loop ③Gate · lessons *"구현자≠verifier"* 와 **동일 명제**. 외부 독립 확증 1건.
- **10(파일당 작성자 1명·병렬 쓰기 때만 격리)** = [Forge Spec-Gate (why-was-fable-banned) — 차용 해체](forge-spec-gate.md) worktree-accept · CLAUDE.md §"충돌 방지"(동시 편집 금지)와 정합. 다만 원문은 *회피*가 아니라 *격리 후 병합*이라 vault 보다 한 칸 적극적.
- **08·13(판단은 모델, 제어흐름은 코드 / 배리어는 예외)** = vault **Deterministic-First** 계열. [Is Grep All You Need? — 에이전트 검색에서 grep vs 벡터 RAG (arXiv 2605.15184)](../techniques/agentic-search-grep-vs-vector.md) 의 "하네스가 검색을 지배" 와 같은 층.
- **04(에이전트는 판단용)** = Karpathy #2(Simplicity First)의 오케스트레이션판.
- ⚠️ **충돌 아님, 스코프 차이**: 본 세션 하네스는 *"작가 명시 요청 없이 workflow 금지"* 규율 하에 있다. 즉 그래프 설계 지식은 흡수하되 **자동 발동은 금지** — 원문 14단계의 "매 작업 워크플로 계획 모드"는 vault 에 부적합.
