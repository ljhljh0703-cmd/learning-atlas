# 사람 프로필을 파일로 붙드는 법 — polysona 구현 흡수

> **한 줄**: 사람의 정체성을 AI 가 한 번에 규정하게 두지 말고, **원발화 로그 · 결정 성향 · 표현 규칙 · 채널 패턴을 파일로 갈라** 추적하되, 압축·적용·승격은 사람 확인 뒤에만 한다.

⛔ **제품은 쓰지 않는다.** 아래는 전부 *구현 방법*이다.

## 1. 세 파일로 가른다

| 파일 | 담는 것 | 섞으면 생기는 사고 |
|---|---|---|
| `persona` | 무엇을 중시하고 **어떻게 결정하는가** | — |
| `nuance` | **어떻게 말하고 쓰는가**(말투·문체·플랫폼별 표현·피할 문구) | 「어느 채널에서 쓰던 말투」가 **정체성으로 굳는다** |
| `accounts` | **어디서 누구에게 어떤 패턴**을 쓰는가 | 프로젝트 전용 취향이 **전역 프로필로 오염**된다 |

vault 대응 — PERSONALIZATION 의 golden·project-only 경계, SKILL 의 용도별 문체 분리가 이미 *내용*으로는 이 셋을 나눠 갖고 있다. **없던 것은 그 경계를 파일 단위로 못박는 것.**

## 2. 행마다 출처 칸 (PLOON 형식)

마크다운을 그대로 데이터로 읽는 얇은 형식이다. 파서 40줄이면 된다.

```
## core
[table#1](layer,value,source)
unconscious-self|빠른 실행과 반복으로 의미를 만드는 사람|McAdams
conscious-ideal|단순하고 명확한 것을 추구|Laddering

~2026-08-27: 원발화 그대로 — append 만 한다
```

- `## 이름` = 구획 · `[표이름#N](열,열,열)` = 헤더 · `|` 로 값 · `~날짜:` = **append-only 로그 줄**.
- ⭐ **가져올 핵심 = 열에 `source` 가 항상 있다.** 프로필의 *한 줄마다* 어디서 나왔는지가 붙는다. 요약본만 남고 근거가 사라지는 실패를 파일 형식이 막는다.
- 사람이 그냥 읽고 손으로 고칠 수 있으면서 기계가 파싱한다 — 별도 DB 없이 vault 와 같은 성질.

## 3. 원증거와 압축본을 분리한다

- 인터뷰 원문·장면·출처는 **append-only 로그**. 고칠 때는 과거를 덮어쓰지 않고 **정정 항목을 새로 붙인다.**
- 현재 프로필 본문은 언제든 **원로그로 되짚어 재검산**할 수 있어야 한다.
- 🔴 **원 제품에 빠진 것** — profiler 와 orchestrator 를 말로만 나눴을 뿐, **압축 전에 사람 승인 게이트가 없다.** 흡수한다면 그 경계를 반드시 추가한다.

## 4. 권한 사다리

```
원증거(raw evidence)   : append-only · 수정 금지
프로필 후보            : 에이전트가 제안 가능
확정 프로필            : 사람 승인 필요
생성된 지시문          : staged only — 활성 지시 파일에 직접 복사 금지
프로젝트 활성화        : 프로젝트별 명시 선택
```

- 에이전트가 **추론한** 정체성을 활성 `AGENTS.md`·`CLAUDE.md` 에 직접 쓰지 않는다. 내보내기는 별도 폴더에 두고 「복사 전 검토」로 남긴다. (vault 의 HITL 스테이징과 같은 방향 — 더 강하게 적용)
- 피드백 **한 건**을 전역 정체성으로 올리지 않는다.
- 프로필은 **선택지를 좁히는 보조 정보**이지 사람의 결정을 대신하는 제약이 아니다.

## 5. 훅으로 강제하는 법 (구현)

- **세션 시작 훅** — 활성 프로필의 앞부분과 **핵심 규칙 3~4줄**을 세션 머리에 출력한다. 규칙이 문서 깊숙이만 있으면 긴 세션 후반에 흐려진다(= agent-harness §주입 표면과 같은 원리, 훨씬 싼 구현).
- **쓰기 전 훅** — 프로필 파일에 Write 가 닿으려 하면 **읽었는지 먼저 경고**한다. "압축 본문은 덮어쓰지 말고 로그에 append 하라"를 도구 단에서 상기시킨다.
- 활성 프로필은 `_active` 파일 한 줄로 가리킨다 — 전환이 파일 하나 교체다.

## ⛔ 가져오지 않는 것 (명시 배제)

| 버린 것 | 왜 |
|---|---|
| 심리학 10개 프레임워크를 **사실 추출기**로 사용 | 서로 다른 전통·목적·검증 수준을 「10개」라는 숫자로 묶었다. `defense-bypass prompts`·무의식 패턴 추출 같은 표현은 사람을 **진단 대상**으로 만든다. 자기보고 한 번을 안정된 성격 사실로 승격할 위험. **임상 도구가 아니다.** |
| 가상 팔로워 점수 | API 가 **원고 본문을 읽지 않는다.** 입력은 프로필 id·팔로워 id·차원·**제목 문자열**뿐이고, 문자열 해시로 `40 + |hash % 56|` = 40~95 를 만든다. 대시보드의 hook/공감/공유/CTA 점수는 **결정론적 데모 숫자**다. 반응 예측·A/B 근거로 쓰면 안 된다. |
| 팔로워 인구통계 역할극 | 성별·연령·직업이 고정 배열. 실제 독자 근거가 아니다. |
| live 검색 없을 때 합성 주제를 「현재 trend」로 라벨링 | fallback 자체는 UX 상 유용하나 **관측된 것과 유도한 것을 라벨로 갈라야** 출처가 안 무너진다 |

## 게임 쪽으로 가져갈 때

창작자 프로필과 NPC 프로필을 **같은 저장구조에 합치지 않는다.** NPC 는 `정본 증거 / 행동 정책 / 목소리 / 관계 상태` 가 맞다. 플레이어 반응 시뮬레이터는 인구통계 스테레오타입이 아니라 **실제 플레이테스트·텔레메트리·held-out 시나리오**에 근거해야 한다.

## 다음 검증 후보

1. **출처 스키마** — 프로필의 각 주장이 어느 작가 발화·교정·승인에서 왔는지 claim 단위로 링크되는 최소 스키마.
2. **프로젝트 전용 프로필 전환** — 포폴·게임·창작 셋을 전역 오염 없이 바꿔 끼우는 읽기 전용 파일럿.
3. **실제 독자 평가** — 역할극 대신 held-out 피드백·플레이테스트로 채점자를 보정.
